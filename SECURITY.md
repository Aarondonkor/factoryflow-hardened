# FactoryFlow Security, Privacy and Operations Policy (implementation baseline)

**Access:** Auth and roles are derived exclusively from trusted Supabase profiles and authorization checks inside SECURITY DEFINER functions. Public registrations are customers awaiting approval. Administrators issue staff invitations, and special direct database access must be logged and limited. Conduct monthly reviews of administrator, HR and sales accounts; deactivate departed staff accounts.

**Payments:** Never persist Paystack secret keys in the SPA, Git or local browser storage. Log only transaction references, amounts, currency, order and provider status; avoid full payment card numbers, session tokens or private webhook contents. Store all keys in Supabase Edge Function secrets. Paystack settlement/refunds must be independently verified, with webhook signature verification and a periodic reconciliation job. Compare provider settlements, cash deposits, bank transfers, refunds and your payment ledger daily.

**Sensitive HR data:** Ghana Card numbers, salaries, attendance, contact information and next-of-kin details are sensitive. Give payroll/employee read permission only to approved administrators and HR users, and read/write only through permitted RLS rules. Remove Ghana Card collection if unnecessary. Review Supabase backups, database export permissions, project admin access and any third-party storage. Encrypt backups, restrict access, rotate keys on departure/incident, and do not send employee records via unsecured email.

**Retention:** Set and publish a jurisdiction-appropriate retention period for HR records, payroll, transaction receipts and audit logs based on Ghanaian legal/accounting advice. Do not automatically purge immutable financial records without an approved compliance process. Establish a request process for access, correction and deletion subject to regulatory retention requirements. Record permission grants/revocations and security incidents.

**Incident readiness:** Monitor anomalous signup role claims, repeated checkout failures, discrepant payment references, stock movements, excessive login failures, and privileged RPC errors. On suspected compromise, disable checkout, rotate exposed tokens, revoke malicious auth sessions, reconcile warehouse and payments, investigate audit logs, and notify impacted parties as legally required.

**Deployment:** Keep `.env`, API service-role keys, Paystack secrets, database backups, and `node_modules` out of source archives; use environment-specific configuration and restricted CI secrets. Only serve over HTTPS. Pin deployment dependencies with the lockfile, run code/security checks on every merge, and review the Content-Security-Policy against the live browser console before go-live.
